---
title: "在浏览器中使用 OpenIDEA"
description: "在容器或工作区中运行 openidea-server --listen，通过浏览器使用 OpenIDEA，无需在本机安装桌面端。"
---

`openidea-server --listen` 向浏览器提供 OpenIDEA 工作台。项目、语言服务器、终端、运行和 Git 都在服务端所在的地方（容器、云工作区、远程机器），
浏览器只显示界面。适用于无法安装桌面端的场景，例如在某个端口上提供网页 IDE 的工作区平台。

<Warning>这是早期版本。使用前请阅读[限制](#限制)。</Warning>

## 启动

先构建一次前端，然后在项目旁启动服务端：

```bash
pnpm build:web
openidea-server --listen 0.0.0.0:8080 --project /workspace/my-app --web-root dist
```

服务端会打印带访问令牌的地址：

```text
OpenIDEA is ready: http://0.0.0.0:8080/?token=3f9c…
```

打开一次即可。服务端会设置 Cookie，并把令牌从地址栏中移除。

| 选项                       | 含义                                                                            |
| -------------------------- | ------------------------------------------------------------------------------- |
| `--listen [<host>:]<port>` | 监听地址。只写端口时仅监听 `127.0.0.1`；要接受外部连接请使用 `0.0.0.0:<port>`。 |
| `--project <path>`         | 每个新浏览器标签页打开的文件夹。服务端信任该文件夹，因此不会弹出信任提示。      |
| `--web-root <dir>`         | 已构建的前端。默认为 `$OPENIDEA_WEB_ROOT`、二进制旁的 `web/` 目录或 `./dist`。  |
| `--token <secret>`         | 使用指定的访问令牌，而不是随机令牌（也可设置 `OPENIDEA_TOKEN`）。               |
| `--no-auth`                | 不使用令牌。仅当服务端前面已有其他认证时使用。                                  |

## 安全

服务端能以其用户身份运行任意命令（终端、运行配置）。请把对其端口的访问权限视同 shell 访问权限。

- 默认需要令牌。请把它当作 SSH 密钥，而不是可重复使用的密码。
- 每个 WebSocket 必须来自页面自身的来源（`Origin` 与 `Host` 或 `X-Forwarded-Host` 一致），因此同一浏览器中的其他页面无法使用你的会话。
- 服务端使用明文 HTTP。在暴露到可信网络之外前，请放在 TLS（工作区代理、反向代理）之后。
- 使用 `--no-auth` 时，任何能访问该端口的人都能以服务端用户身份运行代码。

## 在代理之后

页面及其套接字使用相对地址，因此只要代理转发 WebSocket 升级并保留末尾的斜杠，IDE 就能在
`https://lab.example.com/user/project/proxy/8080/` 这样的路径前缀下工作。服务端每 20 秒发送一次 WebSocket ping，避免空闲超时断开连接。

## 开发容器

```json title=".devcontainer/devcontainer.json"
{
  "forwardPorts": [8080],
  "postStartCommand": "openidea-server --listen 0.0.0.0:8080 --project ${containerWorkspaceFolder} --token \"$OPENIDEA_TOKEN\" &"
}
```

请把 `OPENIDEA_TOKEN` 设为工作区的机密，这样重启后地址保持不变。

## 限制

- **一个标签页就是一个会话。** 每个浏览器标签页启动自己的后端。重新加载页面或连接中断会结束其终端、运行和调试会话；项目及其文件不受影响。
- **只有一个窗口。** 设置、差异、比较和编辑器窗口在桌面端是独立窗口，目前尚无法打开。
- **仅限服务端命令。** 仅桌面端提供的功能（Docker、GitHub 拉取请求、HTTP 客户端、插件管理、系统通知、纯文本以外的剪贴板）不可用，并会报告不可用。
- **项目磁盘上的图片和文件**：桌面端通过 `asset:` 协议显示的内容目前不提供。
- **没有 MCP 服务。** 此模式下服务端不会为编码代理启动 MCP 端点。
- **打开和保存对话框**在应用内浏览服务端的文件。不支持“另存为”。
